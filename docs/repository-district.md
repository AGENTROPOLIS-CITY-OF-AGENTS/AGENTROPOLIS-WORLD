# Repository District

Repository District is the governed 3D operational index for repositories across `AGENTROPOLIS-CITY-OF-AGENTS` and `WIREDCHAOS`.

It extends the existing AGENTROPOLIS-WORLD city. It is not a separate world, dashboard, bookshelf, or authority system.

## Spatial grammar

| City element | Repository meaning |
| --- | --- |
| Organization zone | GitHub owner or organization |
| Building | Repository |
| Height | Activity and scale, normalized per organization |
| Width | Functional scope |
| Floors | Packages, services, or major modules |
| Rooms | Components, classes, functions, and workflows |
| Streets | Dependencies and integration paths |
| Transit lines | Dispatch and cross-repository event routes |
| Lit windows | Active agents, workflows, or deployments |
| Construction crane | Active pull request or build |
| Red beacon | Security finding or failing required check |
| Dim building | Stale repository |
| Green perimeter | Healthy and policy-compliant repository |
| Empty parcel | Planned repository not yet implemented |

## Building interior

Entering a building reveals repository identity, ownership, license, languages, packages, dependencies, agents, mandates, issues, branches, pull requests, CI, deployments, security findings, BUZZ activity, Hermes handoffs, and Sentinel-6 receipts.

## Authority boundary

The district is read-only by default. A click, gesture, navigation event, visualization state, or agent presence signal never grants authority.

Consequential actions must pass:

```text
Identity -> Mandate -> AEGIS -> Tool Permission -> Execution -> Receipt -> Sentinel-6 Audit
```

Until an event is backed by an authorized receipt, the renderer must label it `preview`, `simulated`, `pending`, or `unverified`.

## Data contract

Repository metadata enters through governed manifests. Tokens and private repository contents never enter the browser bundle. The public spatial plane receives only the minimum fields required to render approved state.

The initial scene uses procedural massing. Repository-specific buildings will replace placeholder massing as signed repository manifests become available.

## Reference boundary

The Git City is a product reference for a living contribution-driven skyline. Repository District uses AGENTROPOLIS architecture, visual identity, governance, and original implementation. It does not copy The Git City code, branding, pixel-art language, social shop, or profile-building model.
